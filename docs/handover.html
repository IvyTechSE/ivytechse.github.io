Orientering

Vad det är

En statisk sajt utan server, utan databas och utan runtime att övervaka. Det som kan gå sönder är bygget eller deployen — aldrig sajten mitt i natten.

Sajt
ivytech.se — publik marknadssajt, en startsida plus /tjanster/ och /om-ivy/ Domänen pekas mot GitHub Pages. CNAME och public/CNAME i repot måste båda innehålla domänen.
Ramverk
Next.js 14 App Router med output: 'export' Bygget spottar ut ren HTML i out/. Inga serverkomponenter med runtime, inga API-routes, ingen ISR.
Hosting
GitHub Pages från branchen gh-pages gh-pages är en byggartefakt. Committa aldrig dit för hand.
CSS
Egen CSS i app/styles/, inget ramverk Lagerindelad: config/ (tokens, media queries) → base/ → elements/ → patterns/. Lägg nya sektionsstilar i patterns/.
Bilder
Egen ResponsiveImage, inte next/image images.unoptimized: true — statisk export kan inte optimera bilder. Varianter genereras i förväg med ffmpeg.
Test
Jest + Testing Library i __tests__/ npm test. Testerna är strukturella — de kontrollerar att fält finns, inte vilka namn eller hur många.
Tillgänglighet
Uttalat mål: WCAG 2.2 AA eslint-plugin-jsx-a11y i linten, Lighthouse i CI, prefers-reduced-motion respekteras. Det här är en säljpunkt för Ivy — låt det inte glida.

Den enda filen som spelar roll

app/content.ts

Allt innehåll ligger som exporterade objekt och arrayer. Komponenterna importerar och renderar. Ingen text är hårdkodad i JSX.

Exporterna är navItems, site, hero, servicesSectionIntro, servicesPageHero, services, steps, approachIntro, team, teamIntro, workShowcase, contact och teamPageHero.

Praktisk konsekvens: nästan varje förfrågan från Anna eller en kollega — ny formulering, ny tjänst, ny person, ändrad mejladress — är en ändring i den här filen och inget annat. Det gör sajten ovanligt lätt att underhålla, och det är den viktigaste enskilda saken att ta med sig från den här överlämningen.

Att känna till

TeamSection använder person.email som React-nyckel. Mejladressen måste finnas och vara unik, annars får ni renderingsfel.

De två första korten i team-arrayen får priority och laddas eagert. Ordningen i arrayen påverkar alltså både laddning och den förskjutna reveal-animationen.

Pipeline

Bilder genereras lokalt och committas in

Det finns ingen bildtjänst. Varianterna skapas på din maskin med ffmpeg och checkas in i repot tillsammans med originalet.

npm run images:variants kör scripts/generate-image-variants.sh, som center-croppar till kvadrat och skriver 320 px och 640 px i jpg, webp och avif. ResponsiveImage bygger sedan ut photoBase till en <picture> med avif före webp före jpg.

  1. 01Lägg fornamn-efternamn.jpg i public/images/team/ — gemener, bindestreck, inga å/ä/ö
  2. 02npm run images:variants — kräver ffmpeg i PATH
  3. 03Sätt photoBase: "/images/team/fornamn-efternamn" — utan storlek och utan filändelse

Fällan

Skriptet går igenom alla jpg-filer under public/images/ och skriver över varianterna för hela teamet, inte bara den nya personen. Sist någon lade till en kollega fick det städas upp i efterhand i commit a22c94d.

Gör därför alltid git add på bara den nya personens filer och kasta resten med git checkout -- public/images. Sanity-check: en -320.jpg ska ligga runt 15–30 kB. Är den 1–2 kB har något gått fel i genereringen.

Namngivningen translittererar bort svenska tecken: Pyykkö blir ylva-pyykko, Törnered blir mikael-tornered.

Den viktigaste varningen

Branch-läget ljuger för er

Det finns tre långlivade brancher. Bara en av dem är levande. Avståndet nedan är uppmätt i faktiska commits efter main.

main default · deployar
develop 46 commits efter
master 118 commits efter

stapelns längd = hur aktuell branchen är · main = 2026-04-01

Varför det här biter

master och develop är döda kvarlevor men ligger kvar på origin. I en gammal klon kan origin/HEAD dessutom fortfarande peka på master, så git status hälsar med „main branch: master” och verktyg föreslår PR:er mot fel bas.

Åtgärd nu: radera master och develop på origin. Att låta dem ligga kvar „för säkerhets skull” har inget värde — deras historik finns redan i main, som är en superset av båda. 

# fixa den felaktiga pekaren i din egen klon
git remote set-head origin -a

# städa origin när ni är överens
git push origin --delete master develop

Automatik

Bygg och deploy

Sex workflows i .github/workflows/. Alla delar samma composite action .github/actions/build som kör Node 22, npm install, lint och build.

  • →deploy.yml — push till main bygger och publicerar out/ till gh-pages. Använder clean-exclude: pr-preview så öppna previews inte raderas.
  • →preview.yml — varje PR får en full preview på ivytech.se/pr-preview/pr-{nr}/ och en botkommentar med länken. Katalogen städas automatiskt när PR:en stängs.
  • →ci.yml och test.yml — lint, build och Jest på PR.
  • →codeql.yml — säkerhetsanalys av JS/TS.
  • →lighthouse.yml — prestanda och tillgänglighet enligt .lighthouserc.js.

Previewfunktionen är den bästa vanan i det här repot: merga aldrig en innehållsändring utan att ha tittat på previewen först. Det kostar två minuter och fångar felstavade namn, trasiga bilder och sneda croppar innan de går live.

Läget i backloggen

14 öppna PR:er — alla från bottar

Tolv från GitHubs Copilot-agent och två från Dependabot. Noll från människor. Dessutom tolv öppna issues, i stort sett parvis kopplade till Copilot-PR:erna.

Copilot-PR:erna handlar mest om SEO och infrastruktur: JSON-LD för Organization, Service, Person och BreadcrumbList, saknade tjänsteundersidor, härdade Actions-permissions, branch protection och bundle-size-checkar. Flera är gamla nog att ha konflikter.

Rekommendation

Beta av eller stäng hela högen tidigt. En PR-lista med fjorton oöverblickbara bot-PR:er leder till att ingen tittar på PR-listan alls — och då missar ni den dagen en riktig PR dyker upp.

PR #77 bumpar Next 14.2.35 → 15.5.18. Det är en major-uppgradering som någon måste äga aktivt, inte bara godkänna. Bestäm vem av er två som gör den, och gör den som ett eget spår med preview och Lighthouse-jämförelse.

Koden är det enkla. Det här är sådant som bara går att lämna över medan jag fortfarande har åtkomst.

  • Domänen ivytech.se — vem äger registraren, och vem kan ändra DNS-posten som pekar mot GitHub Pages?

  • Umami Cloud — sajten skickar besöksstatistik till cloud.umami.is (website-ID finns dokumenterat i README). Kontot bakom behöver en ny ägare.

  • CLAUDE.md och docs/agents/ — finns i dag bara i min lokala klon, ocommittade. Antingen checkas de in innan jag går, eller så försvinner de.

Konkret ordning

Första veckan

Numreringen är en faktisk sekvens — varje steg gör nästa lättare.

  1. Klona färskt och verifiera att ni kan bygga

    Inte en kopia av min klon. npm install && npm run lint && npm test && npm run build ska gå igenom rent hos er båda innan något annat.

  2. Städa brancherna

    Radera master och develop. Gör det först — annars kommer varje senare misstag i veckan att gå att skylla på fel bas.

  3. Gör en liten ändring hela vägen till produktion

    Rätta en formulering i content.ts, öppna PR, titta på previewen, merga, se den gå live. Nu har ni sett hela kedjan och behöver aldrig gissa hur den fungerar.

  4. Säkra åtkomsterna

    Gå igenom listan under Ägande utanför koden med Anna medan jag är kvar och kan svara.

  5. Töm PR-högen

    Merga, stäng eller boka in de fjorton bot-PR:erna. Bestäm vem som äger Next 15-uppgraderingen.

  6. Bestäm vem som är förstajour för sajten

    Två utvecklare utan utpekad ägare blir noll utvecklare när Anna behöver en textändring på fredag eftermiddag. Dela upp eller turas om — men bestäm.

Runbook

Byta en person i teamet

Det första ni kommer att göra: ta bort mig och lägga in den nya kollegan. Gör båda i samma PR, så visar previewen hela nya teamsektionen på en gång.

Bra utgångsläge: jag förekommer bara i app/content.ts plus mina bildfiler. Testerna är generiska, så inget testfall behöver ändras.

  1. Utgå från rätt kod

    git fetch origin
git switch -c team/personbyte origin/main
npm install

  2. Ta bort profilen

    Radera hela objektet { name: "Joakim Larsson", … } ur team-arrayen i app/content.ts.

  3. Ta bort bildfilerna

    git rm public/images/team/joakim-larsson*   # 9 filer

    Bilderna finns kvar i git-historiken efteråt. Ska de bort helt krävs en history rewrite på ett publikt repo — separat beslut, inte en del av det här.

  4. Lägg in porträttet och generera varianter

    cp portratt.jpg public/images/team/fornamn-efternamn.jpg
npm run images:variants
git add public/images/team/fornamn-efternamn*
git checkout -- public/images   # kasta omgenererat för övriga

  5. Lägg till profilen

    Nytt objekt sist i team med name, role, intro på svenska, email, linkedin och photoBase.

  6. Verifiera

    npm run lint && npm test && npm run build
npm run dev   # kontrollera /om-ivy/

  7. PR, preview, merge

    Botten kommenterar preview-URL:en. Granska den, merga till main, och deployen publicerar inom några minuter.

Sista ordet
